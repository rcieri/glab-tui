# v0.9.0 — Open PR Test Guide

Per-PR test instructions for the issues still open in the `v0.9.0` milestone.
General prerequisite: `gh pr checkout <N>` on a clean tree, then `cargo run`
against a repo with `gh`/`glab` auth. GitHub features need a GitHub repo;
GitLab features need a GitLab repo.

## PR #358 — list new themes in generated config.toml
Follow-up to #356 (no issue). The generated `config.toml` comment and the
runtime theme list now include the new presets (`oled`, `github-dark-hc`, etc.).

- **Automated:** `cargo build` (doc/comment only, no logic change).
- **Manual:** `cargo run`, trigger a config save (`save_view` key), inspect the
  generated `~/.config/glab-tui/config.toml` — the theme list comment should
  show `oled`, `github-dark-hc` among the options.

## PR #355 — change `'None'` fields to `'--'` (#350)
Empty/missing values render as `--` instead of `None` across the inspector,
edit docs, and the backend milestone/`None` sentinel checks.

- **Automated:** `cargo build`.
- **Manual:** Open an issue/MR with no milestone, assignee, or due date → the
  detail pane shows `--` (not `None`). Create/edit an entity and check the
  milestone selector's "clear" entry is now labeled `--`. Confirm a cleared
  milestone actually clears server-side (the backend now treats `--` as empty).

## PR #334 — allow milestone to be cleared (#326)
Selecting the empty/`--` milestone entry in the edit selector sets the milestone
to `None` instead of creating a milestone literally titled `None`.

- **Automated:** `cargo test test_milestone_removal_clears_milestone_field`
  (unit test added in this PR).
- **Manual:** Edit an issue/MR that has a milestone, pick the blank entry,
  Submit → server milestone clears; reopen and confirm it is empty (`--`).

## PR #333 — selection toggle `V` for issues/MRs (#321)
New `select_mode` (toggle `v`); moving the cursor while in select mode marks
each visited item. **Key remap: `view_diff` default moved `v` → `D`.**

- **Automated:** `cargo build`.
- **Manual:** On Issues/MRs: press `v` → select mode on, current row marked;
  arrow down through several rows → each gets marked. Press `v` again → off.
  Press `D` → opens the diff/view (was `v` before). Verify `Space` still
  toggles individual selection.

## PR #331 — use repo MR/PR templates when creating MRs (#320)
Creating an MR from an issue now shows a template selector (from
`.gitlab/merge_request_templates/` or GitHub) instead of a hardcoded default;
selection stored in `pending_mr_create`.

- **Automated:** `cargo build`.
- **Manual:** On a repo that has MR templates, open an issue, choose create-MR →
  a "Select Merge Request Template" selector appears; pick one → editor opens
  pre-filled with that template (plus `Closes #<iid>`).

## PR #337 — unify API error handling via `App::show_error` (#319)
All backend failures now route through `App::show_error`, which sets the error
toast AND marks the running terminal-command row as `Failed: …`.

- **Automated:** `cargo build`.
- **Manual:** Trigger a failing action (edit an issue while offline / with a
  revoked token) → both the error toast appears **and** the corresponding row
  in the terminal-commands panel shows `Failed: <msg>` (previously only one
  surface updated).

## PR #335 — `EditEntityKind::EditRelease` (#317)
Editing a release now uses a dedicated `EditRelease` kind (was reusing
`CreateRelease` with the wrong entity kind).

- **Automated:** `cargo build`.
- **Manual:** On the Releases tab, open a release's edit menu (`e`) → title reads
  "Edit Release <tag>", Description field is populated from the existing release;
  submit → updates the release (verify on the host) instead of erroring or
  creating a duplicate.

## PR #338 — route entity-edit shortcuts through `keybinding_matches` (#253)
Removes the buggy `edit_issue`/`edit_mr` string duplication and adds remappable
`edit_title` (`t`) and `edit_target_branch` (`g`) shortcuts inside the edit menu.

- **Automated:** `cargo build` (cleans `is_new` → `needs_submit`, dedupes
  `entity_type` matches).
- **Manual:** With an edit menu open, press `t` → jumps to Title field; on an MR
  edit menu press `g` → Target Branch field. Confirm no crash when switching
  fields, and that remapping these in config works.

## PR #330 — GitLab group-level backend methods (#179, partial)
Adds `list_group_issues/mrs/pipelines` to the `Backend` trait. GitLab implements
them (reads `groups/<group>/merge_requests` etc.); GitHub returns "not
supported". **No UI yet** — backend-only scaffolding.

- **Automated:** `cargo build` (trait impls must compile on both backends).
- **Manual:** No UI trigger yet, so TUI testing is not possible; verify it
  compiles on a GitHub checkout (the `Err` stubs) and on GitLab. Group browsing
  UI is the remaining #179 work (recommend keeping #179 open for that).

## PR #341 — Submit/Cancel dialog (replaces confirm popup) (#315)
The YES/NO confirm popup is replaced by a modal with explicit **Cancel / Submit**
buttons and toggleable options (e.g. merge squash/delete-source). Adds
`BulkMergeMrs`. **This PR currently conflicts with `main`** (app.rs, handlers,
main.rs, ui/inspector.rs, ui/overlays.rs).

- **Automated:** `cargo build` + `cargo clippy -- -D warnings` after rebase.
- **Manual (post-rebase):** Trigger any destructive action (close/delete issue
  or MR, merge MR, delete branch/release/milestone) → modal now shows
  Cancel/Submit with any options; `Tab`/`←`/`→` move between rows, `Space`/`Enter`
  toggles an option, Submit runs the action. Test bulk-merge: select multiple
  MRs and merge → `BulkMergeMrs` path.
